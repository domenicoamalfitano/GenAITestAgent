### TASK:

1. Safety First: The primary goal is to improve code structure, readability, and maintainability WITHOUT changing its external behavior.
2. One change: Focus on ONE clear refactoring (e.g. Extract Method, Rename Variable) per attempt.
3. Max Attempts: You have a maximum of 3 attempts to successfully refactor the code and pass all tests.
4. Don't change the name of the class and don't change the name of the public methods.
5. Don't delete the public methods.
5. **Rules of Refactoring:
  - **Extract method**: When the methods are too long or duplicate code.
    Do NOT extract a method when the code block is short, trivial, or only used once.
  - **Rename variable/method**:Rename only if it significantly improves readability, rename it **only if it is not a standard algorithmic variable**.
    Do NOT rename variables commonly used as loop indices or counters in algorithms: i, j, k, n, m, len, size, count.
    Only rename variables/methods when it clearly improves readability without altering behavior.
  - **Simplify conditional/loop**: When the conditional can be more readable without changing behavior.
  - **Inline method/variable**: When the method or variable is trivial (e.g. return a constant or performs a single simple assignment).
    Do not inline methods or variables with complex logic unless it is clearly redundant.
  - **Replace magic numbers**: When it improves readability without changing behavior.
    Do not replace numbers that are self-explanatory (e.g. 0 for a starting index, 1 for increment).
  - **Remove duplicate methods using generic type**: When multiple methods differ only in their return type or the parameters type and share identical logic, consider to create a generic method.
    Do not apply this refactor if the methods are trivial getter/setter without additional logic.
    It is applicable if the repeted logic is significant (e.g. validations, transformations, calculations).
6. If a test fails because it calls a method or accesses a variable that was removed or modified in the source code, you may:
   - Identified that the test failure is due to an outdated method name, parameter list, or field reference.
   - Update only the test calls (method name, parameters, or field accesses) to match the current source code.
   - Do not change the behavior of test.
   - Use write_file_truncate to save the corrected test file.

You must follow these steps scrupulously:

**Step 1: Analyze and apply One Refactoring**
    - Read the sources file you prefer.

    - Analyze the source code and identify ONE SINGLE refactoring opportunity (e.g., "Extract Method," "Rename Variable for clarity," "Remove duplicate if block," "Simplify a loop").

    - Execute write_file_truncate(input='{file_path}|||<complete modified code>').

**Step 2: Run Tests**

**Step 3: Evaluate the Result**
    If all tests pass:
      - The refactoring is successful.
      - Proceed to Step 4.
    
    If tests FAIL:
      - Analyze the errors.
      - If the failure is likely caused by renamed methods or variables:

      - If it can be safely corrected without changing behavior, adjust and retry (up to 3 times).
      - If tests still fail after 3 attempts, restore the previous working code using

        and terminate, communicating that rollback was done.

**Step 4: Continue Refactoring**
    - Re-analyze the updated source code.
    - If you detect another clear refactoring opportunity, repeat Steps 1–3.
    - Continue until the code is clean and no further safe refactoring can be made.
    - When no more changes are needed, provide the final report:
      Final answer: Refactoring complete, code is clean. ✅ All tests passed successfully.
      Never execute another Action after that.
