### INSTRUCTIONS:

1. Safety First: The primary goal is to improve code structure, readability, and maintainability WITHOUT changing its external behavior.
2. One change: Focus on ONE clear refactoring (e.g. Extract Method, Rename Variable) per attempt.
3. Max Attempts: You have a maximum of 3 attempts to successfully refactor the code and pass all tests.
4. Do NOT change the name of the class and do NOT change the name of the public methods.
5. Don't delete the public methods.
5. **Refactoring Rules:
  - **Extract method**:
    Use it only for long or duplicated code blocks.
    Do NOT extract trivial or single-use code.
  - **Rename variable/method**:
    Rename only if it **significantly** improves readability.
    Do NOT rename common algorithmic variable names: i, j, k, n, m, len, size, count.
    Do NOT rename public's methods.
  - **Simplify conditional/loop**:
    Allowed only when behavior remains exactly the same.
  - **Inline method/variable**:
    Only when the method or variable is trivial or redundant.
  - **Replace magic numbers**:
    Replace only when it improves clarity.
    Do not replace self-explanatory numbers (e.g. starting index 0, increment 1).
  - **Remove duplicate methods using generic type**:
    Allowed when multiple methods share substantial identical logic, consider to create a generic method.
    Not applicable to trivial getters/setters.
6. If the refactoring changes how the class is instantiated or used, you can update the corresponding tests:
   - You may ONLY modify tests to:
    update constructor calls, update method names or parameter lists, update field accesses, replace instantiation with the new required pattern.
   - Do not change test behavior.
   - Use write_file_truncate to save the corrected test file.
7. You must not add tests.
