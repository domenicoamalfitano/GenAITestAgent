The goal is to generate a single meaningful new unit test that **FAILS** (Red step of TDD) for a Java Maven project and, if successful, produce a final report.

You MUST call a tool.

You are given:
METHOD UNDER TEST '{method_signature}'
DESCRIPTION OF THE METHOD '{method_description}'
PATH OF THE TEST FILE: '{file_path}'
CURRENT CLASS TEST:
{tests}

***

### TOOL USAGE:
You have access to the following tools:

1. **write_file_truncate**
   - Use this tool to save your complete and formatted Java source code.
   - Use the JSON format.
   - The 'file_path' MUST be a string enclosed in double quotes.
   - Input format: {{
                    "file_path": "{file_path}",
                    "content": "code_content"
                    }}

2. **run_maven_test**
   - Use this tool to run all Maven tests in the project.
   - It returns the test results, including which tests failed and their error messages.

---

### INSTRUCTIONS:

1. **Test Class Structure:** You must write or update a Java test class called **{class_name}Test** in the package `com.example`.
2. **Assumptions:** Assume there is a class called `{class_name}` with the specified method under test. The method is **not static**, so you must instantiate an object of the type `{class_name}` first, using the default constructor.
3. **New Test Rule:** You must **add only one new, meaningful unit test** for the method `{method_signature}` at a time.
4. Always pass only values that are representable by the method’s parameter types, since Java is a statically-typed language.
4. **Imports:** You must import `org.junit.jupiter.api.Assertions` and `org.junit.jupiter.api.DisplayName`.
5. **Preservation:** **Preserve all existing tests** in the file.
6. **Test Naming:** The name of the new test method must be **explicit and descriptive**, clearly indicating the **behavior being tested**.
7. You MUST NOT use Java Reflection. Calls to Class.forName, getMethod, or Method.invoke are strictly forbidden.
8. You must stop immediately after producing a Final Answer.
9. **Do not invent behavior**: Do not invent new behaviors, exceptions, or contract rules not explicitly stated in the method description.
10. There must be exactly one test method for the class constructor, this test must:
    - Instantiate the class using the constructor under test.
    - Verify that each constructor parameter is correctly assigned by calling the corresponding getters using "assertEquals".
11. Don't write tests without Assertion.
12. Use Mockito only when the method under test depends on an external collaborator (another class, interface, service, repository, or gateway) whose real behavior should not be executed during the test.
    - If you want to use Mockito, you can add this imports, if necessary:
        import static org.mockito.Mockito.*;
        import org.mockito.Mockito;
        import org.mockito.Mock;
        import org.mockito.MockitoAnnotations;
13. Do not re-add tests that were removed in previous iterations.

---

### AGENT WORKFLOW:

**Your task is to analyze the input and choose ONE of the two paths below.**

#### PATH A: Tests are Sufficient

    * **Trigger:** You must *internally analyze* the test class and `{method_description}`. If your analysis concludes that the method is already adequately tested, you must choose this path.
    - Your thought process must explain *why* coverage is sufficient.
    - Call `write_file_truncate` saving the current test file unchanged.
    - After using the tool `write_file_truncate`, you MUST immediately return:
        `Final Answer: There are already ✅ enough tests for this method. No new test added.`

#### PATH B: New Test is Needed (TDD Red Loop)

    * **Trigger:** If your *internal analysis* finds a meaningful behavior or edge case from `{method_description}` not covered by the **CURRENT CLASS TEST**, you must choose this path.
    **Step B.1 (Write):**
        - Your thought process must explain *what test is missing* and *why* it will fail.
        - Use the tool `write_file_truncate` with the *new* test added (preserving all old tests).

    **Step B.2 (Run, Analyze and Report):**
        - Use the tool `run_maven_test` to run the tests.
        - **IF** the observation is **BUILD_FAIL** (test failed at runtime) **OR** the observation is a **COMPILATION_ERROR** due to a "cannot find symbol" error related to {class_name} or {method_signature}:
            * **SUCCESS!** The test correctly failed because the functionality or method definition is missing, you MUST immediately return:
                `Final Answer: RED step successful. New failing test added to '{file_path}'. The process is ready for the GREEN (implementation) step.`
        - **ELSE IF** the observation is **BUILD_SUCCESS**:
            * This means the newly added test already passes.
            * The agent must remove the newly added test by rewriting the file with its previous content and you don't write this test in the future iterations, use the tool ' write_file_truncate'.
            * You MUST immediately return:
                `Final Answer: There are already ✅ enough tests for this method. No new test added.`
        - **ELSE IF** the observation is **COMPILATION_ERROR** due to syntax errors (e.g., missing semicolon, wrong import for Junit, type mismatch):
            * **ERROR!** The test is trivial or syntactically broken. It must be corrected before the RED step can be completed.
            * You must use the tool 'write_file_truncate'.
            * **You must to go back to the Step B.1**
